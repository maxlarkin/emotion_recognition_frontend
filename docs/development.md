# Разработка

## Окружение

- Node.js 22 (тот же, что в `Dockerfile`) и npm.
- Браузер Chrome, Chromium или Firefox. Для экрана «Веб-камера» нужны камера и, по желанию, микрофон.

```bash
npm ci          # зависимости строго по package-lock.json
npm run dev     # http://localhost:5173
```

Сервер разработки не проксирует запросы: их обрабатывает заглушка (см. [STUBS.md](../STUBS.md)).

### Проверка без камеры

Chrome умеет подставлять тестовую камеру и микрофон:

```bash
google-chrome --use-fake-device-for-media-stream --use-fake-ui-for-media-stream http://localhost:5173/live
```

Первый флаг даёт тестовое видео и звуковой сигнал, второй разрешает доступ без вопроса.

## Тесты

```bash
npm test                       # все тесты один раз
npx vitest                     # режим наблюдения
npx vitest run src/live        # тесты одного каталога
```

- По умолчанию тесты идут в среде Node. Тесту, которому нужен DOM, первой строкой добавьте `// @vitest-environment jsdom`.
- Имена файлов: `*.test.ts` — чистая логика, `*.test.tsx` — разметка через `renderToStaticMarkup`, `*.dom.test.tsx` — рендер и действия пользователя в jsdom через Testing Library.
- Тесты экранов, которым нужны данные, подменяют `api` через `vi.mock("../api")` и не зависят от заглушки.
- Тесты заглушки (`src/api/stub/stub.test.ts`) идут на поддельных таймерах Vitest и сбрасывают её через `__resetStub()`.
- `src/build/urls.test.ts` проверяет плагин, который не пускает внешние адреса в бандл.

## Сборка

```bash
npm run build      # tsc --noEmit + vite build, результат в dist/
npm run preview    # раздача dist/ для проверки
```

После сборки проверьте, что в бандле нет внешних адресов (то же делает `Dockerfile`):

```bash
grep -rEo "https?://[^\"' )]*" dist | grep -vE "www\.w3\.org/"   # вывод должен быть пустым
```

Адреса пространств имён XML (`www.w3.org`) допустимы. Если сборка упала с `external URL in …`, значит код или библиотека добавили внешний адрес. Если библиотека никогда по нему не обращается (например, это ссылка в тексте ошибки), добавьте его в список `NEVER_FETCHED` в `vite.config.ts`. Если обращается — от такой загрузки нужно избавиться.

### Docker

```bash
docker build -t emosense-frontend .
docker run --rm -p 8080:80 emosense-frontend    # http://localhost:8080
```

Образ собирается в два этапа: `node` собирает `dist/`, `nginx` его раздаёт. `nginx.conf` отдаёт `index.html` для всех путей, чтобы работали маршруты приложения, а файлы из `/assets/` кэширует навсегда (у них хэш в имени). Для `npm ci` при сборке образа нужна сеть.

## Соглашения

- **Тексты интерфейса — на русском.** Числа — с десятичной запятой. Используйте готовые функции из `src/ui/format.ts`: `prob`, `percent`, `fps`, `decimal`, `clock`, `minSec` и подписи `EMOTION_LABEL`, `DECISION_LABEL`, `CAMERA_TYPE_LABEL`.
- **Комментарии в коде — на английском**, короткие, по делу, как в существующих файлах.
- **TypeScript строгий**: `strict`, `noUnusedLocals`, `noUnusedParameters`. Неиспользуемый параметр называйте с подчёркиванием (`_signal`).
- **Цвета и размеры** берите из CSS-переменных `src/styles/tokens.css`, не пишите значения в компонентах.
- **Данные** экраны получают только через `api` из `src/api` и через `appData`. Прямых `fetch` и `WebSocket` в экранах нет.
- **Ключи эмоций** всегда одни и те же: `anger, disgust, fear, happiness, sadness, surprise, neutral`.
- **Без внешних загрузок**: никаких CDN, удалённых шрифтов и картинок. Новую зависимость ставьте через npm, чтобы она попала в бандл.

## Как добавить запрос

1. Опишите типы запроса и ответа в `src/api/types.ts`.
2. Добавьте функцию в заглушку `src/api/stub/index.ts`. Она должна возвращать данные той же формы, что и сервер, и ошибки через `fail("текст")`.
3. Добавьте такую же функцию в клиент сервера `src/api/real.ts` (через `getJson` или `sendJson`).
4. Добавьте её в объект `api` в `src/api/index.ts`.
5. Опишите запрос в [api.md](api.md) и ответ заглушки в [STUBS.md](../STUBS.md).
6. Добавьте тесты: для заглушки в `src/api/stub/stub.test.ts`, для клиента в `src/api/real.test.ts`.

## Как добавить экран

1. Создайте компонент в каталоге своего раздела и верните из него `<main className="content">…</main>`.
2. Добавьте маршрут в `routes` в `src/App.tsx`. Если экрану нужна левая колонка потоков, положите его внутрь `SidebarLayout`.
3. Добавьте пункт меню в `MENUS` в `src/shell/Toolbar.tsx`.
4. Стили добавьте в `src/styles/app.css`.
5. Опишите экран в [screens.md](screens.md).

## Частые проблемы

| Симптом | Что проверить |
|---|---|
| «Доступ к камере запрещён» | Разрешение для сайта в настройках браузера. |
| «Камера занята другим приложением» | Камеру держит другая программа. В Linux: `fuser /dev/video0`. |
| «Браузер не даёт доступа к камере» | Страница открыта не на `localhost` и не по HTTPS. Камера доступна только в безопасном контексте. |
| Нет голоса на экране «Веб-камера» | Переключатель микрофона и разрешение на микрофон. Без микрофона анализ идёт только по видео. |
| Демо-запись не играет | Так и задумано: у демо-записей нет видео (см. [STUBS.md](../STUBS.md)). Загрузите свой ролик, он будет играть. |
| Данные сбросились | Заглушка хранит всё в памяти страницы. После перезагрузки демо-данные начинаются заново. |
